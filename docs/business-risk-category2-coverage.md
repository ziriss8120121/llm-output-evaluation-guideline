# 事業リスク：区分2の網羅性（MECE）検討

## 1. 目的

LLM出力評価における **区分1「事業リスク」配下の区分2** について、網羅性を高め、可能な限りMECEに近い分類を設計するための調査結果を整理する。

本検討の目的は、区分2を最終確定することではなく、既存のAIリスク管理・生成AI評価フレームワークを比較し、以下を明確にすることである。

- 事業リスク配下で考慮すべき主要なリスク領域
- 現在の区分案に不足・重複がないか
- 「区分」と「影響」を混在させていないか
- 区分2をカタログ化する際の根拠

---

## 2. 調査方針

単一のフレームワークだけで区分2を決定せず、以下の3系統を横断して確認する。

1. **AIリスク全般を広く整理したフレームワーク**
2. **生成AI / LLM固有のリスクを扱うフレームワーク**
3. **日本国内でのAI評価・ガバナンスに関するガイドライン**

主な参照文献は以下とする。

| 文献・フレームワーク | 主な役割 |
|---|---|
| MIT AI Risk Repository | AIリスク分類の網羅性確認の主軸 |
| NIST AI 600-1 Generative AI Profile | 生成AI固有・増幅されるリスクの補完 |
| AISI「AIセーフティに関する評価観点ガイド」 | 日本国内における実務的な評価観点への落とし込み |
| AI事業者ガイドライン | 国内事業者としてのガバナンス観点の確認 |
| OWASP Top 10 for LLM / GenAI | セキュリティ観点の詳細化 |
| ISO/IEC 23894 | AIリスクマネジメント全般の考え方の補助 |

---

## 3. 最も参考になる文献

### 3.1 MIT AI Risk Repository

今回の目的に対して、最も参考になるのは **MIT AI Risk Repository** である。

AIリスクに関する多数の既存分類・フレームワークを統合し、リスクを複数のドメイン・サブドメインに整理しているため、区分2の「抜け漏れ」を確認する母集団として利用しやすい。

代表的なドメインは以下。

1. **Discrimination & Toxicity**
    → **差別・有害性**
2. **Privacy & Security**
    → **プライバシー・セキュリティ**
3. **Misinformation**
    → **誤情報**
4. **Malicious Actors**
    → **悪意ある利用者・悪用**
5. **Human-Computer Interaction**
    → **人間とAIの相互作用**
6. **Socioeconomic & Environmental**
    → **社会・経済・環境への影響**
7. **AI System Safety, Failures & Limitations**
    → **AIシステムの安全性・障害・限界**

この分類からは、事業リスクを単に「法令違反」「情報漏洩」などだけで捉えるのではなく、以下のような領域も考慮する必要があることが分かる。

- 差別・公平性
- 有害コンテンツ
- 誤情報
- 悪用
- 人間による過信・依存
- システム上の安全性・制御不能
- 社会・環境への影響

### 3.2 MITの分類設計から得られる重要な示唆

MITでは、AIリスクを整理する際に、**原因（Cause）と、結果として生じる害・影響（Domain / Harm）を分けて扱う**考え方が取られている。

これは今回の区分設計において非常に重要である。

現在検討中の区分2候補には、以下のような分類軸の混在がある。

- コンプライアンス
- 権利侵害
- 情報セキュリティ
- プライバシー
- ユーザー不利益
- レピュテーション
- 業務・事業影響

このうち、

- 権利侵害
- 情報セキュリティ
- プライバシー

などは「何が問題なのか」という **リスクの種類** に近い。

一方で、

- ユーザー不利益
- レピュテーション
- 業務・事業影響

は、リスクが顕在化した結果として **誰に・どのような影響が生じるか** を表している。

この2種類を同一階層に置くと、分類軸が揃わず、MECEになりにくい。

## 4. NIST AI 600-1 Generative AI Profile

NISTの Generative AI Profile は、生成AIで特に重要なリスクを整理している。

主なリスク領域として、以下が挙げられている。

- CBRN Information or Capabilities
- Confabulation
- Dangerous, Violent, or Hateful Content
- Data Privacy
- Environmental Impacts
- Harmful Bias and Homogenization
- Human-AI Configuration
- Information Integrity
- Information Security
- Intellectual Property
- Obscene, Degrading, and/or Abusive Content
- Value Chain and Component Integration

今回の区分2設計に対して、特に重要な補完観点は以下。

- **誤情報 / Confabulation**
- **有害バイアス**
- **人間による過信・依存**
- **知的財産**
- **有害・暴力・差別的コンテンツ**
- **生成AIのサプライチェーン・構成要素リスク**

現在の区分案では、これらの一部が明示的に表現されていないため、抜け確認に有効である。

---

## 5. AISI「AIセーフティに関する評価観点ガイド」

日本のAIセーフティ・インスティテュート（AISI）が公開する評価観点ガイドは、LLM / 生成AIを実際に評価する際の観点として参考になる。

代表的な評価観点として、以下が整理されている。

- 有害情報の出力制御
- 偽誤情報の出力・誘導の防止
- 公平性と包摂性
- ハイリスク利用・目的外利用への対処
- プライバシー保護
- セキュリティ確保
- 説明可能性
- ロバスト性
- データ品質
- 検証可能性
- 観測と制御（AIエージェントを含む拡張観点）

MITが「網羅性確認のための上位分類」として使いやすいのに対し、AISIは、

> そのリスクを実際にどのような評価観点として確認するか

に落とし込みやすい。

そのため、区分2の母集団をMIT等で整理した後、区分3以下や具体的評価項目へ展開する際に有効である。

## 6. AI事業者ガイドライン

日本国内のAI事業者向けガイドラインでは、代表的な共通指針として以下のような観点が扱われている。

- 人間中心
- 安全性
- 公平性
- プライバシー保護
- セキュリティ確保
- 透明性
- アカウンタビリティ
- 教育・リテラシー
- 公正競争確保
- イノベーション

これは事業リスクをMECEに分類するための直接的な分類表ではない。

一方で、作成した区分2カタログについて、

> 日本企業として考慮すべきAIガバナンス上の重要論点が抜けていないか

を確認するためのクロスチェックとして利用できる。

## 7. 現在の区分2案に対する課題

現時点の事業リスク区分2案は以下。

- コンプライアンス
- 権利侵害
- 情報セキュリティ
- プライバシー
- ユーザー不利益
- 不適切・有害出力
- レピュテーション
- 業務・事業影響

この案には、大きく2つの課題がある。

### 7.1 分類軸が混在している

例として「著作権侵害」を考える。

著作権侵害は、

- 権利侵害
- コンプライアンス違反
- レピュテーション毀損
- 金銭的損失
- ユーザー・第三者への不利益

の複数に該当し得る。

このとき、

- 「権利侵害」はリスクの種類
- 「レピュテーション毀損」「金銭的損失」は影響

である。

これらを同じ区分2に並べると、分類が重複する。

### 7.2 LLM固有リスクが不足している

文献との比較から、少なくとも以下は明示的に検討する必要がある。

- 公平性・差別
- 誤情報・情報完全性
- 悪用・目的外利用
- 人間の過信・依存
- システム安全性・制御不能
- ロバスト性
- 社会的影響

---

## 8. MECE化に向けた設計方針

区分2は、以下の問いに統一するのが望ましい。

> **何が問題なのか**

つまり、区分2では「リスクの種類」を分類する。

一方で、以下は区分2とは別の属性として管理する。

### 影響対象

- ユーザー
- 自社
- 第三者
- 社会

### 影響種類

- 金銭
- 法務
- レピュテーション
- 身体・精神
- 業務
- その他

この構造にすることで、同じリスクについて、

> 何が問題か

と

> 問題が起きた場合に誰へ何の影響があるか

を分離できる。

## 9. 区分2候補（暫定）

文献を横断して整理すると、現段階では以下を区分2候補として検討する価値がある。

| 区分2候補 | 主な内容 | 主な根拠 |
|---|---|---|
| 公平性・差別 | 属性等による不公平、差別、バイアス | MIT / NIST / AISI / AI事業者GL |
| 有害・危険コンテンツ | 暴力、差別、攻撃、危険行為等 | MIT / NIST / AISI |
| プライバシー・個人情報 | 個人情報の不適切利用・推論・出力 | MIT / NIST / AISI |
| 情報セキュリティ | 情報漏洩、攻撃誘発、脆弱性悪用等 | MIT / NIST / AISI / OWASP |
| 誤情報・情報完全性 | ハルシネーション、誤認誘導、虚偽情報 | MIT / NIST / AISI |
| 権利・知的財産 | 著作権、商標、肖像、その他第三者権利 | NIST / 国内法務観点 |
| 悪用・目的外利用 | 詐欺、攻撃、危険用途、想定外用途 | MIT / NIST / AISI |
| 人間の自律性・過信 | AIへの過度な依存、判断委譲、操作 | MIT / NIST |
| 安全性・危害 | 身体・精神その他の安全上の危害 | MIT / NIST / AISI |
| システム障害・制御不能 | 意図しない挙動、ロバスト性不足、制御不能 | MIT / NIST / AISI |
| 社会・環境への影響 | 雇用、格差、競争、環境等の広範な影響 | MIT / NIST |

> NOTE: 上記は確定版ではない。今後、区分同士の重複・粒度・今回の「LLM出力評価」というスコープとの適合性を検証する。

---

## 10. 次に実施すること

区分2を確定する前に、以下のクロスマッピングを行う。

```text
MIT AI Risk Repository
        ×
NIST Generative AI Profile
        ×
AISI 評価観点
        ×
現在の区分2候補
```

その上で、以下を実施する。

1. 同義・類似リスクを統合する
2. 原因・リスク・影響が混在していないか確認する
3. 「LLM出力評価」のスコープ外を除外する
4. 区分2同士の重複を確認する
5. 各区分に「適用判断の目安」を定義する
6. 実案件を複数当てて不足・重複を確認する

最終的には、区分2を **標準候補カタログ** として管理し、案件ごとに全候補について対象 / 対象外を判断し、その理由を記録する。
