# 事業リスク：区分2の選定根拠

## 1. 目的

本ドキュメントでは、LLMを用いた機能実装における**出力評価**について、区分1「事業リスク」配下の区分2をどのような根拠で設定したかを整理する。

想定する利用例は以下のようなLLM機能である。

```text
求人票
  ↓
LLM
  ↓
スカウト文面自動生成
```

このほか、求人要約、検索条件生成、レコメンド理由生成等、他のLLM機能実装にも横展開することを想定する。

本検討では、既存のAIリスク・AIセーフティの文献から広くリスク候補を抽出した上で、今回の「LLM出力評価」というスコープに照らして取捨選択する。

目的は以下の2点である。

- **網羅性の向上**：担当者の思いつきだけで評価観点を決めず、既存フレームワークを母集団として検討する
- **説明可能性の向上**：なぜその区分を採用し、なぜ他の区分を除外したかを説明できるようにする

---

## 2. 結論

現時点では、事業リスクの区分2を以下の5区分とする案を採用する。

1. **公平性・差別**
2. **有害・危険コンテンツ**
3. **誤情報・誤誘導**
4. **プライバシー・機密情報**
5. **権利侵害**

ただし、これは全AIリスクを網羅する分類ではない。

> **「LLM機能の出力を評価する」という本ガイドラインのスコープに必要な事業リスクを抽出した結果**

である。

また、案件固有のリスクが存在する場合は、区分2またはその配下の区分を追加できるものとする。

---

## 3. 今回の評価スコープ

### 3.1 対象

LLM機能が生成した**出力内容そのものから確認できる事業リスク**を評価対象とする。

例えば以下を対象とする。

- 差別的・偏見を含む出力
- 暴力、犯罪、攻撃、ハラスメント等につながる出力
- 入力情報や事実と異なる出力
- 個人情報・機密情報の不適切な出力
- 第三者の権利を侵害する出力

通常利用時だけでなく、必要に応じて異常入力・目的外利用等をテストケースとして与え、その結果として生成される出力も評価する。

### 3.2 対象外

以下は重要なAIリスクではあるが、本ガイドラインの**LLM出力評価そのものとは別の評価領域**として扱う。

#### システムセキュリティ評価

例：

- Prompt Injection等に対するシステムの耐性
- 認証・認可
- API・ネットワークの脆弱性
- モデル、コード、モデルウェイトへの不正アクセス
- ソフトウェア・依存コンポーネントの脆弱性
- システム停止・改ざんへの耐性

なお、攻撃の結果として**機密情報がLLM出力に漏えいしたか**を確認すること自体は、本ガイドラインの「プライバシー・機密情報」で評価できる。

つまり、

```text
なぜ漏えいできたか
→ システムセキュリティ評価

実際の出力に漏えいが発生したか
→ LLM出力評価
```

と役割を分離する。

#### AIシステム・モデル品質評価

例：

- モデル自体のロバスト性
- モデルの能力・性能
- システム全体の可用性
- モデルの説明可能性・解釈可能性
- モデルの学習データ品質
- AIシステム全体の検証可能性

これらの結果として発生する「誤った出力」は本ガイドラインで評価するが、原因となるシステム特性そのものは別評価とする。

#### ガバナンス・ライフサイクル評価

例：

- AIシステムの開発・提供体制
- 責任分界
- モデル・サービス調達
- サプライチェーン管理
- モニタリング体制
- インシデント管理

#### 社会・環境レベルのリスク評価

例：

- AI利用による雇用構造への影響
- 市場競争への影響
- 権力集中
- AI利用に伴う環境負荷

これらは個別機能の出力内容を評価する本ガイドラインより上位の事業・AIガバナンス領域として扱う。

# 6. NIST Generative AI Profileからの候補抽出

NIST AI 600-1が挙げる12リスクについても同様に整理する。

| NISTリスク | 今回の扱い | 理由 / 対応先 |
|---|---|---|
| CBRN Information or Capabilities | **統合** | 危険情報の出力として「有害・危険コンテンツ」 |
| Confabulation | **採用** | 「誤情報・誤誘導」 |
| Dangerous, Violent, or Hateful Content | **採用** | 「有害・危険コンテンツ」および一部「公平性・差別」 |
| Data Privacy | **採用** | 「プライバシー・機密情報」 |
| Environmental Impacts | **スコープ外** | 環境・インフラレベルのリスク |
| Harmful Bias or Homogenization | **採用** | 「公平性・差別」 |
| Human-AI Configuration | **原則スコープ外** | 利用設計・Human-AI Interaction評価。出力上の誤誘導は「誤情報・誤誘導」 |
| Information Integrity | **採用 / 統合** | 「誤情報・誤誘導」 |
| Information Security | **一部スコープ外** | システム脆弱性はセキュリティ評価。出力への機密漏えいは「プライバシー・機密情報」 |
| Intellectual Property | **採用** | 「権利侵害」 |
| Obscene, Degrading, and/or Abusive Content | **採用** | 「有害・危険コンテンツ」 |
| Value Chain and Component Integration | **スコープ外** | サプライチェーン・システム構成・調達の評価 |

NISTでは同一リスクが複数のカテゴリにまたがり得ることも明記されている。そのため、NISTの12リスクをそのまま区分2として採用するのではなく、本ガイドラインの評価対象に合わせて再編する。

# 7. AISI評価観点からの候補抽出

AISI「AIセーフティに関する評価観点ガイド」第1.20版では、LLMシステムに関する既存の10評価観点と、AIエージェント特有の評価観点が整理されている。

| AISI評価観点 | 今回の扱い | 理由 / 対応先 |
|---|---|---|
| 有害情報の出力制御 | **採用** | 「有害・危険コンテンツ」 |
| 偽誤情報の出力・誘導の防止 | **採用** | 「誤情報・誤誘導」 |
| 公平性と包摂性 | **採用** | 「公平性・差別」 |
| ハイリスク利用・目的外利用への対処 | **別軸** | 区分ではなくテストシナリオとして扱う |
| プライバシー保護 | **採用** | 「プライバシー・機密情報」 |
| セキュリティ確保 | **一部スコープ外** | システムへの不正操作・停止等はシステムセキュリティ評価。出力への情報漏えいは「プライバシー・機密情報」 |
| 説明可能性 | **スコープ外** | システム特性・透明性の評価。案件要件として必要な場合はビジネス価値側で扱う |
| ロバスト性 | **スコープ外** | システム・モデル品質評価。結果として出る誤りは出力評価側で検知 |
| データ品質 | **スコープ外** | 学習・参照データの管理はデータ / システム評価 |
| 検証可能性 | **スコープ外** | 開発・提供・運用を通じた検証可能性はガバナンス / システム評価 |
| 自律的な挙動 | **スコープ外** | AIエージェント特有のシステム評価 |
| 外部環境との相互作用 | **スコープ外** | AIエージェント特有のシステム評価 |

AISIはAIセーフティ評価をLLMの出力だけでなく、AIシステムそのものを対象としている。そのため、AISIの評価観点のうち、今回の出力評価に直接対応するものだけを抽出する。

# 8. 候補を再編する際のルール

外部フレームワークから抽出した候補を、そのまま区分2として並べると分類軸が混在する。

そのため、以下のルールで再編する。

## 8.1 区分2は「出力に何の問題があるか」で統一する

区分2は、以下の問いに回答する分類とする。

> **このLLM出力には、どの種類の事業リスクが含まれているか。**

したがって、原因、利用者の意図、結果として生じる損害は原則として区分2には置かない。

## 8.2 「悪用・目的外利用」はテストシナリオ軸とする

悪用・目的外利用は「出力に何の問題があるか」ではなく、**どのような条件でLLMが利用されたか**を表す。

例えば、悪意ある入力によって詐欺文面が生成された場合、

```text
テストシナリオ
→ 悪用・目的外利用

出力リスク
→ 誤情報・誤誘導 / 有害・危険コンテンツ
```

と整理する。

この分離により、通常利用・異常利用のどちらでも同じ区分2を利用できる。

## 8.3 コンプライアンスは横断的な確認軸とする

「コンプライアンス」を区分2とすると、以下のように他の区分と重複する。

```text
差別的出力
→ 公平性・差別
→ 法令違反の可能性

個人情報漏えい
→ プライバシー・機密情報
→ 法令違反の可能性

著作権侵害
→ 権利侵害
→ 法令違反の可能性
```

そのため、コンプライアンスは独立した区分2ではなく、各評価項目について**関連法令・社内規程への抵触有無を確認する横断属性**として扱う。

## 8.4 ユーザー不利益・金銭損失・レピュテーションは「影響」とする

これらはリスクの種類ではなく、リスクが顕在化した結果である。

例：

```text
誤情報
  ↓
ユーザーが誤認
  ↓
応募・意思決定への不利益
  ↓
企業の信用低下
```

そのため、区分2とは別に必要に応じて以下のような影響属性を持たせる。

- ユーザーへの影響
- 自社への影響
- 第三者への影響
- 法務・コンプライアンス影響
- 金銭的影響
- レピュテーション影響
- 身体・精神への影響

# 9. 最終的な区分2案

## 9.1 公平性・差別

### 定義

人種、性別、年齢、国籍、障害、宗教等の属性やその他の背景を理由として、不公平な扱い、偏見、差別、ステレオタイプ等を含む出力。

### 主な根拠

- MIT: Discrimination & Toxicity
- NIST: Harmful Bias or Homogenization
- AISI: 公平性と包摂性

### スカウト文面生成の例

- 性別・年齢等に基づき不適切に候補者を評価する表現
- 特定属性を前提としたステレオタイプな表現

---

## 9.2 有害・危険コンテンツ

### 定義

人の生命・身体・精神・財産等への危害、違法行為、暴力、攻撃、ハラスメント、性的・侮辱的表現等につながる出力。

### 主な根拠

- MIT: Exposure to toxic content
- MIT: Malicious Actorsの一部
- NIST: CBRN Information or Capabilities
- NIST: Dangerous, Violent, or Hateful Content
- NIST: Obscene, Degrading, and/or Abusive Content
- AISI: 有害情報の出力制御

### スカウト文面生成の例

- 候補者を侮辱・攻撃する表現
- ハラスメントに該当し得る表現
- 違法・危険行為を推奨する内容

---

## 9.3 誤情報・誤誘導

### 定義

入力情報や事実と異なる内容、根拠のない情報、誤解を招く表現、虚偽・誇張等によって利用者や第三者を誤った判断へ誘導する出力。

### 主な根拠

- MIT: Misinformation
- NIST: Confabulation
- NIST: Information Integrity
- AISI: 偽誤情報の出力・誘導の防止

### スカウト文面生成の例

- 求人票に存在しない年収・福利厚生を生成する
- リモート勤務不可の求人を「フルリモート可」と表現する
- 求人の魅力を事実以上に断定する

---

## 9.4 プライバシー・機密情報

### 定義

個人情報、センシティブ情報、社内機密、営業秘密等を、必要性や権限なく取得・推論・開示・出力するリスク。

### 主な根拠

- MIT: Compromise of privacy
- NIST: Data Privacy
- NIST: Information Securityのうち情報漏えいに関する部分
- AISI: プライバシー保護
- AISI: セキュリティ確保のうち機密情報漏えいに関する部分

### スカウト文面生成の例

- 本来出力対象ではない社内メモ・内部情報を文面に含める
- 不要な個人情報を推測して文面に含める

---

## 9.5 権利侵害

### 定義

著作権、商標権、肖像・パブリシティ等の人格的権利、営業秘密等、第三者が有する権利・利益を侵害する可能性がある出力。

### 主な根拠

- NIST: Intellectual Property
- MIT: Privacy & Security、Socioeconomic & Environmental等に含まれる関連リスク
- AI事業者ガイドライン等の国内ガバナンス・法務観点

### スカウト文面生成の例

- 第三者の著作物を必要以上にそのまま再現する
- 利用許諾のない第三者コンテンツを出力に含める

---

# 10. 区分2の重複を抑えるための分類ルール

AIリスクは実際には相互に関連するため、完全に排他的な分類にすることは難しい。

そのため、区分設計としては分類軸を統一しつつ、1つの出力に複数のリスクが存在する場合は複数区分で評価することを許容する。

判断時の目安は以下とする。

| 問題の中心 | 主に使用する区分 |
|---|---|
| 属性を理由とする不公平・偏見 | 公平性・差別 |
| 暴力・攻撃・危険・ハラスメント等 | 有害・危険コンテンツ |
| 事実誤り・虚偽・誇張・誤解誘導 | 誤情報・誤誘導 |
| 個人情報・秘密情報の不適切な開示 | プライバシー・機密情報 |
| 第三者の法的権利・利益の侵害 | 権利侵害 |

例えば、

> 特定の属性に対する虚偽のステレオタイプを含む出力

であれば、

- 公平性・差別
- 誤情報・誤誘導

の両方で問題となり得る。

MECEは「1つの出力に必ず1ラベルしか付かない」ことではなく、**評価観点の分類軸を揃え、不要な概念重複を減らすこと**を目的とする。

# 11. 実務での適用イメージ

区分2は全案件共通の候補カタログとして提供し、案件ごとに適用要否を判断する。

例：スカウト文面自動生成

| 区分1 | 区分2 | 対象 / 対象外 | 判断理由 |
|---|---|---|---|
| 事業リスク | 公平性・差別 | 対象 | 採用領域であり、属性に関する不適切表現が候補者へ不利益を与える可能性があるため |
| 事業リスク | 有害・危険コンテンツ | 対象 | 候補者へ直接提示される文章であり、不適切・攻撃的表現を防ぐ必要があるため |
| 事業リスク | 誤情報・誤誘導 | 対象 | 求人票に存在しない条件を生成した場合、候補者の意思決定を誤らせるため |
| 事業リスク | プライバシー・機密情報 | 対象 | 内部情報等が出力へ混入しないことを確認する必要があるため |
| 事業リスク | 権利侵害 | 対象 | 生成文面を外部へ送信するため、第三者権利を侵害する出力を確認する必要があるため |

案件によって対象外とする場合も、対象外理由を記録する。

本区分2案は、文献調査と今回のLLM出力評価スコープから導出した暫定案である。
